PART B — OWNERSHIP TRANSFER SCRIPT
════════════════════════════════════════
Context: every owned table is scoped by ownerId. Content seeded
under one user is invisible to another. Before handing the site
to Laura, all existing content must move to her account. This
script is also the foundation for agent-to-agent transfer later,
so build it properly rather than as a one-off.

scripts/src/transfer-ownership.ts

  Args (env):
    TRANSFER_FROM_EMAIL
    TRANSFER_TO_EMAIL
    TRANSFER_CONFIRM=yes     -- refuse to run without this

  Behavior:
  1. Resolve both users by email. If either is missing, exit
     with a clear error and change nothing.
  2. Refuse if from == to.
  3. Print a DRY RUN summary first: row counts per table that
     would move. Require TRANSFER_CONFIRM=yes to proceed past
     the summary.
  4. Inside a SINGLE database transaction, update ownerId from
     the source user to the target user across EVERY owned
     table. Enumerate them explicitly — do not reflect over the
     schema, because a table added later must fail loudly rather
     than be silently skipped:
       media, properties, property_media, articles,
       image_slots, slot_assignments,
       transactions, transaction_milestones,
       transaction_documents, transaction_events,
       milestone_templates, milestone_template_items,
       campaigns, campaign_tasks, campaign_assets,
       campaign_events, campaign_templates,
       campaign_template_items,
       marketing_templates
     If any table in this list does not exist, ABORT the whole
     transaction and report which one. Do not partially transfer.
  5. Do NOT touch: users, sessions, auth_events, recovery_codes,
     inquiries. Inquiries are site-level and have no ownerId.
  6. Print a final summary of rows moved per table.
  7. Log a transfer record — insert an auth_events row with
     action 'ownership_transferred' referencing both user ids.

  The whole operation is atomic. A failure mid-way must leave
  the database exactly as it was.
