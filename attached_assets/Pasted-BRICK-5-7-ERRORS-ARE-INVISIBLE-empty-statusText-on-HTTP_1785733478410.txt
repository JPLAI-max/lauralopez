BRICK 5.7 — ERRORS ARE INVISIBLE (empty statusText on HTTP/2)

Root cause, confirmed by reading the code — do not re-diagnose:

admin-api.ts sets the error message from res.statusText, then
overrides it with the JSON error field if present. On HTTP/2
(which Replit dev uses) res.statusText is ALWAYS an empty string.
If the response is not JSON, msg stays "". Login.tsx renders
{error && <p>{error}</p>} — an empty string is falsy, so NOTHING
renders. Every failed login looks like the button did nothing.

1. NEVER PRODUCE AN EMPTY ERROR MESSAGE
   In admin-api.ts, build the message with guaranteed fallbacks:
     - Use the JSON error field if present and non-empty.
     - Else use res.statusText if non-empty.
     - Else use a status-derived string: `Request failed (${res.status})`.
   The thrown ApiError.message must NEVER be an empty string.

2. LOG EVERY FAILURE TO THE CONSOLE
   Before throwing, console.error the method, path, status, and
   response content-type. This is currently invisible.

3. FLAG NON-JSON RESPONSES EXPLICITLY
   If content-type is not application/json, the message must say
   so: `Expected JSON, received ${contentType} (${res.status})`.

4. RENDER ON TRUTHY-OR-EMPTY
   In Login.tsx and TotpSetup.tsx, replace {error && ...} with a
   check on whether a request has failed, not on message
   truthiness. A failed request with a blank message must still
   render something.

5. VERIFY THE PASSWORD ACTUALLY MATCHES
   Separate issue worth checking: seed-admin reported "already
   exists — nothing to do". It is idempotent and does NOT update
   the password of an existing user. If the account was created
   in an earlier run with a different ADMIN_SEED_PASSWORD, the
   current password will not work.

   Add scripts/src/reset-admin-password.ts:
     env: RESET_EMAIL, RESET_PASSWORD, RESET_CONFIRM=yes
     Refuses without RESET_CONFIRM. Requires 16+ chars.
     Updates passwordHash with argon2id. Does NOT touch TOTP.
     Logs a password_reset auth event.

ACCEPTANCE
1. Login with a deliberately wrong password -> a VISIBLE error
   message appears. Screenshot it.
2. Browser console shows the logged failure with status and
   content-type.
3. Confirm ApiError.message is never empty for any status code.
4. Run reset-admin-password, then log in with the new password
   -> reaches the TOTP screen.
