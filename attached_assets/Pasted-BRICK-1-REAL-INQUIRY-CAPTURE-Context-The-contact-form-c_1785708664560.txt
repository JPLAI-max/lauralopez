  fullName      text not null
  email         text not null
  phone         text nullable
  affiliation   text not null

2. API CONTRACT — lib/api-spec/openapi.yaml
────────────────────────────────────────
Add tag `inquiries`. Add path:

POST /inquiries
  operationId: createInquiry
  requestBody: CreateInquiryRequest
  responses:
    201 -> CreateInquiryResponse { id: string, status: string }
    400 -> ErrorResponse { error: string, fields?: object }
    429 -> ErrorResponse
    500 -> ErrorResponse

CreateInquiryRequest schema:
  fullName    string, minLength 2, maxLength 120       required
  email       string, format email, maxLength 254      required
  phone       string, maxLength 40                     optional
  affiliation string, maxLength 60                     required
  inquiryType string, maxLength 60                     required
  message     string, minLength 10, maxLength 4000     required
  website     string                                   optional (honeypot)

Then run: pnpm --filter @workspace/api-spec run codegen

3. ROUTE — artifacts/api-server/src/routes/inquiries.ts (new file)
────────────────────────────────────────
POST /inquiries handler:

  a. Validate body with the generated Zod schema. On failure return 400
     with per-field errors. Do NOT swallow validation errors.

  b. HONEYPOT: if `website` is a non-empty string, return 201 with a
     fabricated id and write NOTHING to the DB. Silent discard — the
     bot must not learn it was caught.

  c. RATE LIMIT: max 5 submissions per IP per hour. On exceed, return
     429. Use an in-memory Map with timestamp pruning.
     Add a code comment: in-memory limiter does not survive autoscale
     multi-instance; move to a DB-backed counter before real traffic.

  d. Whitelist `affiliation` and `inquiryType` against the exact enum
     values in ContactForm.tsx. Reject anything else with 400.

  e. Insert into DB. If the insert throws, log via pino and return 500.
     THE HANDLER MUST NOT RETURN A SUCCESS RESPONSE ON A FAILED WRITE.

  f. AFTER a successful insert, attempt the Resend notification inside
     its own try/catch. If email fails, log the error and STILL return
     201. Email failure must never lose a lead.

  g. Return 201 { id, status: "received" }.

Register in artifacts/api-server/src/routes/index.ts.
