2. DATE ENGINE — api-server/src/lib/dates.ts
────────────────────────────────────────
computeMilestoneDate({ anchorDate, offsetDays, direction, dayType })

  calendar: add or subtract offsetDays directly.
  business: skip Saturdays, Sundays, and dates in a holiday list.
            Holiday list is a module constant array of ISO dates
            covering the next 2 years of US federal holidays —
            include it, do not fetch it.

  If the anchor date is null, return null. Never guess an anchor.

Recompute rule: when acceptanceDate or closeOfEscrowDate changes,
recompute computedDate for every milestone on that transaction.
NEVER touch overrideDate on recompute — a manual override always
wins and survives anchor changes. Write a dates_changed event
with the full before/after milestone set.

Unit test the engine directly: weekend rollover, month boundary,
year boundary, holiday adjacent to a weekend, negative offsets
(before COE), null anchors.

────────────────────────────────────────
3. STATUS SEMANTICS — read carefully
────────────────────────────────────────
A deadline passing does NOT complete or remove a milestone.
"Overdue" is DERIVED, never stored:

  overdue = status === 'pending' AND effectiveDate < today

For milestones with requiresWrittenRemoval, "complete" requires
removalDeliveredAt to be set. A pending milestone past its date
with requiresWrittenRemoval true is the loudest state in the UI —
that is the gap where deals go wrong.

Derive status colours client-side from effectiveDate and today.
Do not run a cron that mutates rows to 'overdue'.

6. ICS FEED — public route, token-authenticated
────────────────────────────────────────
GET /api/calendar/:icsToken.ics    (NOT under /api/admin)

  - Look up transaction by icsToken. Unknown token -> 404, and do
    NOT reveal whether it ever existed.
  - Emit VEVENTs: one all-day event per pending or complete
    milestone, using effectiveDate. UID stable per milestone id so
    updates replace rather than duplicate.
  - SUMMARY: "{label} — {propertyAddress}"
  - Include a VALARM 1 day prior on pending items.
  - Cache-Control: no-cache. Content-Type: text/calendar.
  - Rate limit by token: 60 req/hour.

Build the ICS string manually or with a small library — do not
pull in a heavy calendar dependency.

Detail page shows the subscribe URL with a copy button and a one
line note that anyone with the link can see the dates.
