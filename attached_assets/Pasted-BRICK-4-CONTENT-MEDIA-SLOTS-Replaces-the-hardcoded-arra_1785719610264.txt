BRICK 4 — CONTENT, MEDIA & SLOTS

Replaces the hardcoded arrays in MarketIntelligence.tsx, 
TopPicks.tsx, Listings.tsx, and Sold.tsx with DB-backed content, 
plus a media library with named image slots.

Every table gets ownerId (notNull, indexed) and officeId 
(nullable) — same rule as Brick 3.

────────────────────────────────────────
1. STORAGE — Cloudflare R2
────────────────────────────────────────
Env (do NOT prompt for these — defer like Resend):
  R2_ACCOUNT_ID, R2_ACCESS_KEY_ID, R2_SECRET_ACCESS_KEY,
  R2_BUCKET, R2_PUBLIC_BASE_URL

If unset, the media module must degrade: log at info, and upload
endpoints return 503 with "Storage not configured." The app must
boot and every other feature must work. Same pattern as mailer.ts.

Use @aws-sdk/client-s3 against the R2 endpoint. Presigned PUT for
upload — do NOT proxy file bytes through the API server.

────────────────────────────────────────
3. UPLOAD PIPELINE
────────────────────────────────────────
POST /api/admin/media/presign  { filename, mimeType, sizeBytes }
  -> { uploadUrl, storageKey }
  Reject non-image mimeTypes. Reject over 25MB.

POST /api/admin/media/complete { storageKey, filename, mimeType }
  Server fetches the object, reads real dimensions with `sharp`,
  generates WebP derivatives at 480/960/1440/2400 (never upscale),
  writes them to R2, inserts the media row.

  Do NOT trust client-reported dimensions. Read them server-side.

  If sharp fails, delete the uploaded object and return 422.

────────────────────────────────────────
4. SLOT MATCHING — the "use this for..." prompt
────────────────────────────────────────
GET /api/admin/media/:id/slot-suggestions

  Return only slots where:
    - media.width >= slot.minWidth, AND
    - |media.aspectRatio - slot.aspectRatio| / slot.aspectRatio
      <= 0.25

  Never suggest a slot the image would obviously break. A 3:4
  portrait must not appear for a 21:9 hero. This filter is the
  whole feature — a suggestion that looks broken kills trust in
  the tool permanently.

  Sort by closest ratio match. Include each slot's current image
  thumbnail so she sees what she'd be replacing.

POST /api/admin/slots/:slotKey/assign { mediaId, propertyId? }
  Closes the prior slot_assignments row (sets unassignedAt),
  opens a new one, updates image_slots.

POST /api/admin/slots/:slotKey/revert
  Reassigns the immediately previous assignment.

NEVER auto-assign. Every assignment is an explicit user action
following a preview.

6. FOCAL POINT + SERVING
────────────────────────────────────────
Public image component reads focalX/focalY and emits
object-position. Emit srcset from derivatives with sizes
appropriate to the slot. Always include alt text — fall back to
the property address if altText is null, never to the filename.

8. TRACK RECORD — properties are never deleted
────────────────────────────────────────
When a Top Pick sells, it does NOT get removed. Status moves to
'sold', soldPrice and soldDate are filled, and the original
commentary stays intact and visible.

Public Top Picks page shows current picks first, then a
"Previously featured" section where each sold entry displays
Laura's original commentary alongside what it actually closed at.
That accumulating record is the point — it is the public evidence
that her calls were right.

Never hard-delete a property. Add an `archived` boolean if
something must be hidden.
